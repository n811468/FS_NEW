# 車型損益試算系統 — 使用說明

個人/小組使用版本（無登入權限控管、無情境鎖定、部門/科目可自由新增；圖表由前端自己產生 SVG，不載入任何外部程式庫）。
打開方式、資料包的匯出/匯入/合併見 `../local/README.md`；資料結構見 `data-schema.md`，架構見 `architecture.md`。

## 開始使用

用 Chrome / Edge 雙擊 `dist/FS-local.html`。第一次打開是空的資料庫（只有內建科目），可以：

- 「匯入資料包…」載入同事給的或自己備份的資料包；
- 「更多…」→「載入示範資料」先看看（Gate F 現況、由它衍生的目標情境、另一個車型 DE）；
- 或直接照下面的順序從「車型主檔」開始建立。

## 使用順序

前端導覽以「車型」為最上層選單，「情境」是車型底下的次要選單。
**所有頁面都是表格式編輯**：一次看到全部資料、直接在格子裡改、最後按一次「儲存」，
不必先按「編輯」才能動某一列。主檔類頁面（車型/車系/科目設定）另有「新增一列」，
填好後跟其他修改一起送出。

1. 「車型主檔」新增車型（`DA`、`DE`...）—— 必須先有車型，才能往下建立車系。代號建好後仍可以
   按「重新命名」改，系統會自動把車系/情境等所有引用該代號的資料一併更新，不會留下對不到的孤兒資料。
2. 「車系設定」新增該車型底下的車系（3人貨車 / 9人客貨車...）。之後的輸入頁面都會依此自動帶出車系欄位；
   車系代號同樣可以用「重新命名」改，銷售構成/銷貨成本/營業費用/費率覆寫都會一併跟著改。
   「排序」欄位可以直接填數字調整車系顯示順序，留空排最後；這個順序會套用到所有用車系排欄位的頁面
   （銷貨成本、營業費用、稅務費用比率、儀表板的車系選單...），不必每個頁面各自調。
3. 「情境設定」選 GATE 別（GATE F~A、Z）、自訂情境名稱、選情境性質（現況/目標）。
   同一個 GATE 下可以有多個情境，例如「GATE F 現況」「GATE F 目標」。
   新增情境時可以選一個**來源情境當基礎**，銷售構成／銷貨成本／開發總投／營業費用／費率
   會整批複製過來，只要改幾個數字就好（「GATE F 目標」以「GATE F 現況」為底，
   下一版目標又以上一版目標為底）。也可以把既有情境的資料帶進目前已選取的情境。
   只能在同一個車型底下帶入 —— 跨車型的車系對不上，會產生看不見卻仍被計入損益的資料。
4. 「銷售構成」表格已依車系自動列好。填車型月總台數與構成比，台數自動算出；
   直接改台數則構成比自動回算，兩者永遠一致（構成比合計不是 100% 時會標紅提醒）。
   LC總台數 = 月台數 × 12 × LC年限，即時顯示。
5. 「銷貨成本」矩陣表格：一列 = 一個成本項目，一欄 = 一個車系，直接填金額。
   成本項目可直接在這一頁新增/刪除；幣別選了非台幣，就自動用「匯率設定」的現況匯率換算。
   最右邊那一欄是**加權平均**（Σ(金額×構成比)÷Σ構成比），不是跨車系的合計 ——
   不同車系的單台成本相加沒有意義，加權平均才跟儀表板的加權平均欄位同一個口徑。
   表格最下面另外列出唯讀的「自動計算」科目(模具/設備攤提、貨物稅等)，讓 B 銷貨成本在這頁就看得到全貌；
   貨物稅那一列滑鼠移過去可以看到完整計算過程(廠價、扣除項、完稅價格、稅率、結果逐步列出)。
6. 「開發總投」逐列填**部門**（自由輸入）→ **大類**（設備/模具/費用）→ **攤提落點**（該大類底下
   實際要攤到哪個損益科目），同一個部門底下可以分好幾列分別選設備/模具/費用，各自攤到不同科目。
   選好之後表格下方會列出各落點的投資總額與單台攤提(總額為 0 的落點不顯示)；沒有想要的落點
   可以在表格上方「新增攤提科目」自己新增（選大類 + 填名稱即可，例如要把「模具」拆成更細的
   「XXXX模具」，新增後就是損益表上一個獨立的科目，且會出現在「模具」大類底下），
   新增的科目一樣不能在「銷貨成本」「營業費用」頁面手動輸入，避免跟開發總投攤提的金額重複計列。
   現況情境不會出現挑戰低減目標欄位；
   目標情境才有，且可用「從其他情境帶入」把現況資料整批複製過來再填低減目標。
7. 「營業費用」同樣是矩陣表格，科目一樣可以在該頁新增/刪除，最右邊同樣是加權平均，
   下面也有唯讀的自動計算科目(季Margin、開發總投攤提的費用類科目)。
8. 「稅務費用比率」只需填「全車系適用」一欄；某個車系費率不同時才填該欄，留白就沿用全車系值。
   沒設定過的比率會帶入系統預設值，確認後按儲存即可。
9. 「匯率設定」以幣別管理（1 外幣 = ? 台幣），可自行新增幣別。只有一種「現況匯率」，
   銷貨成本與開發總投的外幣金額都用它換算。
10. 「損益儀表板」的「選擇車型/情境/車系」跟「已加入的比較欄位」收在同一張卡片，
    加入比較欄位（車型 × 情境 × 車系或加權平均）可跨車型／跨 GATE 並排比較；
    「加入該情境全部車系」可一鍵展開單一情境的所有車系；每個比較欄位可用左右箭頭調整排列順序。
    版面比照實際損益試算表：每個比較欄位分「金額」與「%」兩小欄，全部科目明細都會列出，
    明細科目縮排在它的小計底下，小計/毛利/淨利整列反白；B/E/G/I 四個大項小計前面有收合箭頭，
    點了就把底下的明細列整個收合起來，方便只看大項或只看某一段明細，表格上方也有「全部收合/展開大項」。
    % 基準可切成**廠價(未稅)**或收入(A)；柱狀圖跟它的科目勾選框(其實就是圖例，順便顯示金額參考值)放在一起，
    勾了就在旁邊即時重畫。科目名稱後面的公式（如「營業淨利(=I-J)」）、自動計算科目的來源、
    貨物稅的完整計算過程，平常都隱藏，滑鼠移到 ƒ 圖示或藍色圓點上才顯示提示框
    （提示框自己算位置，不會被表格的橫向捲動裁掉，鍵盤 Tab 也能切過去看）。
    每次計算都會把 A=P8+P9、B=Σ成本明細、C=A-B、E=C-Σd、G=E-Σf、I=G-Σh、K=I-J 重算一次核對，
    對不起來會直接在表格上方示警，不必自己拿計算機加。

> 「科目設定」頁的科目代碼由系統自動編號（父科目字首 + 流水號，如 b15、d6），不需要自己填。
> 結構科目與自動計算科目的名稱寫的就是它的公式，由程式決定，不開放修改也不能刪除；
> 開啟頁面時會自動把它們對回程式碼，所以不會出現「欄位名稱跟數字對不起來」的情形。
> 自己改過的明細科目名稱要一次回復，按該頁的「恢復內建科目預設值」。

## 損益公式

```
P3 建議零售價(不含強配,含稅) = P1 建議零售價(含稅) - P2 強配件售價
P5 實際零售價(含稅)          = P3 - P4 廢車處理費(未稅登打時會先換算成含稅)
P6 營業稅                    = P5 × 營業稅率 / (1 + 營業稅率)          → 取整數
P7 銷售佣金                  = (P5 - P6) × 銷售佣金率                  → 取整數，基礎為未稅零售價
P8 廠價(未稅)                = P5 - P6 - P7
P9 強配收入(未稅)            = P2 ÷ (1 + 營業稅率)
A  收入(未稅,含強配)         = P8 + P9
B  銷貨成本  = 各成本項目合計（含自動帶入的模具費用、新增專屬設備、貨物稅）
C  生產毛利  = A - B
E  銷貨毛利  = C - 廣宣費用 - 促銷 - 批標售 - 季Margin - 索賠
G  產品貢獻  = E - 直接歸屬費用-CMC&SDM - 車型專案開發費用-CMC - 車型專案開發費用-BASE廠
I  營業淨利(未扣前瞻) = G - 固定營業費用-CMC&SDM - 品牌廣宣費用 - 特別加發
K  營業淨利  = I - 前瞻費用
```

## 自動計算的科目（不需手動輸入，避免重複計列）

| 科目 | 來源 |
|---|---|
| P1~P9 售價結構（營業稅、銷售佣金、廠價...） | 銷售構成的售價欄位 + 稅務費用比率 |
| 開發總投的攤提落點科目（內建 b5/b8/f3/f4，可自己新增更多） | 開發總投(該落點的金額加總) ÷ LIFE CYCLE 總台數 |
| b13 貨物稅 | (廠價 − 水平配件外移調降 − 廣宣/促銷/批標售/季Margin) × 完稅價格計算率(91%) ÷ (1+貨物稅率) × 貨物稅率 |
| d4 季Margin（原 0.5%Margin） | 廠價(未稅) × 季Margin率 |

> 開發總投的攤提金額：現況情境用原始金額，目標情境才套用挑戰低減目標%。
> 攤提分母（LIFE CYCLE 總台數）可在開發總投頁單獨設定「攤提基準」台/月 × 12 × 年，
> 留空才沿用銷售構成推算值 —— 實務上兩者常不同。
> 貨物稅的計算過程在「銷貨成本」頁就看得到（滑鼠移到 b13 那一列的金額上）：
> 廣宣/促銷/批標售/季Margin 這四項本來就會從完稅價格裡扣除，不是另外的手動調整項。

> 本系統的計算已用實際 Gate F 損益試算 Excel（DA 車 3 車系 + 加權平均）逐項對帳，數字完全一致。
> 對帳是可重跑的：在專案根目錄執行 `node tools/verify-gatef.js`，
> 它會在記憶體版的試算表上跑完整條真實路徑（建表 → 用系統自己的 save 函式輸入 → 計算），
> 再把每一格跟 Gate F 表上的數字比對（317 格，容差 2 元 —— 表上每格都是四捨五入後的整數，
> 系統則一路帶小數算到最後，小計會累積約 1 元的差）。
> `node tools/verify-features.js` 則驗這一版新增的行為（情境帶入、科目自動編號、匯率精簡等）。

## 已知簡化（相對於原始 Gate F Excel）

- 營業稅、銷售佣金、季Margin 用「稅務費用比率」設定的比率計算，未逐車系個別調整佣金級距；
  如需要特定車系不同費率，在該頁面該車系的欄位填上覆寫值即可（留白就沿用全車系值）。
- 開發總投不再有 TNCAP 對應/不對應欄位；要比較有無 TNCAP 的差異，
  請在同一個 GATE 下開兩個情境（如「GATE F 對應TNCAP」「GATE F 不對應TNCAP」）並排比較。
- 沒有實作情境鎖定/核准流程、沒有登入權限分級（依你先前確認為個人使用，皆非必要）。
