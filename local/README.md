# 地端版（單一 HTML 檔 + 資料包）

跟 MGPA 工具組同樣的用法：**不需要 Google 帳號、伺服器、網路或安裝任何東西**。
把 `dist/FS-local.html` 複製到電腦任何位置，用 Chrome / Edge **雙擊**就能用。
所有資料只存在你這台電腦的瀏覽器裡，不會上傳到任何地方。

後端是 `src/*.gs`（計算引擎與資料存取），前端是 `src/index.html` / `style.html` / `src/ui/*.js`，
build 時原封不動放進這一個檔案。`tools/verify-local.js` 會用 Gate F 實際數字逐格確認算出來的結果正確。

## 日常使用

頁首下方多了一條地端版工具列：

| 按鈕 | 用途 |
|---|---|
| 使用者：XXX | 點一下填自己的名字，會記在稽核紀錄與匯出的資料包上（地端版沒有 Google 帳號可用） |
| 匯出全部 | 整份資料庫存成一個資料包（`FS資料包_全部_日期.json`），**這是備份** |
| 匯出目前車型 | 只匯出上方選的車型，交給同事合併 |
| 匯入資料包… | 選檔後可選「合併匯入」或「取代整個資料庫」 |
| 更多… | 載入示範資料、清空所有資料 |

**修改會自動暫存在瀏覽器裡**，關掉再打開資料還在。但瀏覽器暫存不是正式保存：
清除瀏覽資料、換電腦、換瀏覽器就會不見。所以工具列會顯示「N 次修改尚未匯出」，
**請養成定期「匯出全部」的習慣**，把資料包存到共用資料夾或自己的備份位置。

## 多人協作：每人負責自己的車型

1. 每個人在自己電腦上維護自己負責的車型。
2. 要給別人看時，選好車型 →「匯出目前車型」→ 把檔案放到共用資料夾。
3. 其他人「匯入資料包…」→「合併匯入」，就能在儀表板上跟自己的車型並排比較。
4. 對方之後改了數字，再給一包新的、再合併一次即可（同一個車型以新資料包為準，不會重複）。

合併的規則：

- **資料包裡有的車型，以資料包為準整個取代**（車系、情境、所有輸入資料）；資料包裡沒有的車型完全不動。
  誰負責的車型，誰的資料包說了算。合併前會列出哪些車型會被取代、哪些是新增，確認後才寫入。
- **科目表跟著車型走**：每個車型各自一份科目表，合併時資料包裡的車型連同它的科目表一起取代，
  兩個人各自新增的科目就算代碼相同(都是 b15)也互不干擾，不需要改號。v1 的資料包(只有一份全域科目表)
  合併進來時，那份科目表視為資料包裡每個車型自己的科目表。
- 自訂參數(參數與比率頁新增的)：本機沒有的才加進來，同名參數保留本機的定義。改善作法、科目說明跟著情境走。
- 車系代號在本機屬於別的車型時會擋下來，請先在其中一邊改名。
- 沒有掛在情境底下的全域參數，本機已經有的不會被覆蓋。

## 從 Excel 轉資料包

`dist/FS-excel-to-pack.html` 是另一個雙擊即用的單一檔案，把現有的 Excel 損益試算表(FS)轉成資料包：

1. **選擇 Excel 檔**(.xlsx)。讀的是 Excel 存檔時算好的數字；版面相同的其他分頁可以一起勾選，每個分頁變成一個情境。
2. **確認欄位**：系統猜好科目名稱欄、各車系的金額欄(會排除百分比欄、外幣欄)、加權欄與說明欄，可以改。
3. **逐列對應**：依 Excel 的小計公式判斷每一列 ——
   純加總的列(`=D15+SUM(D21:D32)`)是小計、被加的列是它的明細；「上一段 - 扣項」的列(`=D13-D14-SUM(D33:D38)`)
   串成損益鏈，扣項裡的加總列就是 B 銷貨成本、起點就是收入。售價列(建議零售價、廢車處理費、構成比…)依名稱判斷。
   Excel 的損益鏈段數比系統少時，最後一段對到 K，沒用到的 E/G/I 照上一段金額顯示。
4. **車型與情境**：車型代號、每個分頁的情境名稱/GATE/性質；營業稅率、銷售佣金率由 Excel 的營業稅、佣金列反推。
5. **建立並驗算**：用跟地端版同一套後端在記憶體裡建好資料，逐格跟 Excel 比對(含加權欄)，不相同的列標紅。
   通過後下載資料包，在地端版「匯入資料包…」→「合併匯入」。

小計由系統依科目樹計算，所以逐格比對能驗出漏列或掛錯小計。明細的 Excel 公式會盡量轉成系統公式
(第 3 步「系統怎麼算」欄顯示轉好的公式，或帶入數字的原因；可以整體關閉或逐列關閉)：

| Excel 的寫法 | 轉成 |
|---|---|
| 同一車系欄的其他列 `(D16+D17)*$O$7`、`SUM(D21:D31)` | 科目：`([材料成本K(CIF)] + [海運BAF]) × [關稅率]` |
| 固定的參數儲存格 `$O$7`(左邊標籤「關稅率」) | 參數 `[關稅率]`，每個情境帶自己分頁的值；比率以 % 儲存；標籤跟內建參數同名(貨物稅率)就用內建的 |
| 同一列的外幣欄 × 參數 `E16*$B$4`(RMB 欄) | 車系別參數 `[材料成本K(CIF)(RMB)]` × `[CNY匯率]`(匯率寫進匯率設定) |
| 各車系公式不同 | 車系個別公式 |
| 有的車系是數字、有的是公式 | 帶入數字 + 公式車系用車系個別公式 |
| `頂規 = 入門`(`=D22`) | 各自帶入相同數字(註明照抄) |
| 只有常數的公式 `=3800*1.05` | 帶入數字 |
| 引用其他車系欄做運算、其他分頁、略過的列、`VLOOKUP`/`IFERROR` 等系統沒有的函式、文字 | 帶入數字並說明原因 |
| 同一列在不同分頁(情境)的公式不一樣 | 帶入數字(科目表是同一個車型共用的) |
| 轉成公式卻跟 Excel 算出來不一樣(例如 Excel 的 `-2^2` = 4) | 驗算時自動改回帶入數字，結果頁列出是哪幾列、為什麼 |

**開發總投攤提**另外處理：單台攤提帶入數字的話，改台數、損益兩平、目標情境的挑戰低減都不會連動，
GATE 報告的「開發總投 by 部門」也是空的。所以工具會把單台攤提的公式一路追進開發總投分頁，
展開成「Σ 部門投資 ÷ 攤提台數」，建成**開發總投攤提**科目 + 開發總投頁的部門明細 + 情境的攤提基準台數：

| 會遇到的情況 | 對策 |
|---|---|
| `=開發總投!C22`，C22 = `C20/$B$27`，C20 = `SUM(C5:C19)` | 展開到各部門的投資(C5…C19)，÷ B27；攤提大類(模具/設備/費用)依欄標題 |
| 一個總額拆成兩列：CMC開發費 = `E22 - E23`(費用總計 - 上汽開發費) | 係數相消，上汽那一筆只留在上汽開發費 |
| 中間的彙總格有標籤(`I23 = I21 - I22`，那列寫「CMC費用」) | 有 SUM、除以儲存格、或相對參照同一欄的格子都當彙總繼續展開，不當成一筆投資 |
| 部門投資本身是算式(`E5 = 9000000*$E$2/0.8+…` 含匯率換算) | 整格當一筆投資，金額用 Excel 算好的值 |
| 攤提台數、L/C 月數放在別的格子(`B25` 50,000、上方「L/C月」60) | 找出台數與附近的月數 → 情境的攤提基準(月台數 × 12 × 年) |
| 各情境引用不同的開發總投分頁(低減 10% 版) | 每個情境各自展開，各自一組部門投資與攤提台數 |
| 低減版寫成「原始 × (1 - 低減率)」(`I6 = E6*(1-$G$3)`) | **目標**情境帶原始金額 + 挑戰低減%(GATE 報告看得到低減前後)；現況情境帶低減後金額 |
| 頂規 = 入門(`G23 = D23`) | 展開結果相同，全車系共用同一組投資 |
| `ROUND(總額/台數)`、各車系來源不同、除以兩種台數、兩格相乘 | 帶入數字並說明原因(系統的攤提算不出一樣的數字) |
| 同一個情境裡不同列的攤提台數不一樣 | 系統一個情境只有一個攤提台數，跟多數不同的列帶入數字 |
| 單台攤提是直接打的數字(沒有公式可追) | 名稱像開發攤提(模具/設備/治具/檢具/開發…)時可以勾「用攤提台數回推」：投資 = 單台 × 攤提台數 |
| 展開後算出來跟 Excel 不一樣 | 驗算時自動改回帶入數字 |

整張是**貼上值**(沒有公式)時，小計改由數字推斷：某一列剛好等於緊接的一段列的合計，或等於「上一段 - 中間各項」。
因為會計恆等式兩個方向都成立，用科目名稱分方向 —— 毛利/淨利/貢獻/損益/經銷價這類「結果」列只會是「上一段 - 扣項」，
成本、費用列只會是加總；推斷出來的算式在 Excel 公式欄以「由數字推斷」顯示，一樣可以逐列調整。

對應設定(含逐列關閉的公式、改過的參數名稱)會記在瀏覽器裡，同一份 Excel 換新版時直接沿用。

## 取代整個資料庫

適合還原備份或換電腦：目前瀏覽器裡的所有資料都換成資料包的內容（包含資料包裡沒有的車型會被清掉）。
建議先「匯出全部」再取代。

## 注意事項

- 同一個檔案不要同時開兩個分頁編輯。一邊存檔後，另一邊會停止寫入並提示重新整理，避免互相覆蓋。
- Chrome / Edge 對所有用雙擊打開的本機 HTML 共用同一份暫存，所以同一台電腦上的兩份 `FS-local.html`
  副本會看到同一份資料。要分開管理請用匯出/匯入。
- 無痕視窗或公司政策封鎖暫存時，工具列會出現紅色警告：資料只在這一頁的記憶體裡，關閉前務必匯出。
- 資料包是 JSON 純文字，沒有公式、沒有計算結果（PLResult 隨時可以重算）。欄位名稱跟 `docs/data-schema.md` 的分頁欄位相同。

## 開發者

```
local/
├─ gas-shim.js   # 瀏覽器版的 Apps Script 模擬層(記憶體試算表、LockService、Session...)
├─ pack.js       # 資料包格式：匯出、讀取檢查、只取部分車型、合併(含科目改號)
├─ host.js       # 後端主機：.gs 後端 + 暫存 + google.script.run 替身
├─ boot.js       # 開機：在前端程式執行前架好主機
├─ local-ui.js   # 地端版工具列與匯入對話框
└─ local-ui.css
├─ xlsx-reader.js     # 讀 .xlsx(zip + XML，不靠外部程式庫；共用公式、合併儲存格)
├─ excel-formula.js   # Excel 公式 → 系統公式(參數、匯率、車系個別公式、轉不過去的原因)；貼上值時由數字推斷小計
├─ excel-amort.js     # 開發總投攤提：把單台攤提追進開發總投分頁，展開成 Σ 部門投資 ÷ 攤提台數
├─ excel-pack.js      # Excel 轉資料包：版面/角色判斷、用後端 API 建資料、逐格驗算(對不起來的公式自動改回數字)
├─ excel-pack-ui.js   # Excel 轉資料包畫面(excel-pack.html / excel-pack.css)
tools/build-local.js   # 組成 dist/FS-local.html 與 dist/FS-excel-to-pack.html(各自是單一檔案)
tools/verify-local.js  # Node 驗證：數字與驗算層相同、暫存、資料包、合併
tools/e2e-local.js     # 瀏覽器端對端測試(需要 Playwright，找不到時略過)
```

改了 `src/` 或 `local/` 之後：

```bash
node tools/build-local.js     # 重新產生 dist/FS-local.html
node tools/verify-local.js    # 會檢查 dist 是不是最新的
node tools/e2e-local.js       # 有 Playwright 時跑瀏覽器測試
```

`.gs` 被整段包進 `FSBackendFactory(G)` 函式裡，跟前端程式的全域名稱互不干擾；
`G` 是模擬的 Apps Script 全域物件。每次前端呼叫都比照 Apps Script「每次都是新的執行」清掉單次執行快取，
參數與回傳值都走一次 JSON，跟 `google.script.run` 的序列化行為一致。
